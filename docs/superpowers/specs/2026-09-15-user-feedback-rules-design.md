# 사용자별 "하지 말 것" 목록 — 설계

2026-09-15 초안(JSON 규칙 저장) → 2026-09-23 개정: 사용자마다 markdown 파일 하나로 바꿨다.
구현: `server/storage/prohibitionsStore.ts`, `server/chat/prohibitionDetect.ts`,
`server/routes/prohibitions.ts`, `src/components/ProhibitionsDialog.tsx`.

## 문제

사용자가 "영어로 답하지 마", "표로 만들 필요 없어" 라고 말해도 그 말은 그 대화 안에서만
통한다. 새 대화에서는 같은 지적을 되풀이해야 한다.

## 목표

- 사용자가 **하지 말라는 뉘앙스**로 한 말을 찾아 그 사용자 전용 목록에 모은다.
- 목록은 그 사용자의 **모든 대화** 시스템 프롬프트에 반영된다.
- 사용자는 설정 메뉴에서 목록을 **보고 직접 고친다.**
- 목록이 길어지면 공통된 것을 **묶어서 줄인다.**

## 핵심 결정

### 1. 파일은 사용자마다 markdown 하나

`{DATA_DIR}/owners/<id>/prohibitions.md`. 사람이 직접 읽고 고치는 것이 주된 사용법이라
JSON 보다 markdown 이 맞다. 소유자 폴더 안에 두어 계정 삭제 때 함께 지워진다.

```markdown
# 하지 말아야 할 것
<!-- 설명(반영되지 않음) -->
- 영어로 답하지 않는다          ← 반영

## 검토 대기
- 표를 쓰지 않는다 <!-- 2026-09-23 · "표로 만들 필요 없어요" -->   ← 반영 안 됨
```

`## 검토 대기` 줄이 경계다. 위는 반영, 아래는 후보. HTML 주석은 반영할 때 걷는다.

### 2. 자동으로 찾은 것은 검토 대기로만 간다

사용자 자신의 상황에 대한 불평("이 에러가 안 사라져요")을 앱의 행동에 대한 불만으로 잘못
읽은 한 줄이 곧바로 반영되면, 이후 모든 대화가 틀린 제약을 받는데 사용자는 이유를 알 수 없다.
그래서 감지 결과는 검토 대기에만 쌓이고, 사용자가 위로 옮겨야 효력을 갖는다.
설정 메뉴 항목에 검토 대기 개수가 뱃지로 보인다.

### 3. 감지는 답변 옆에서 돌고 아무것도 기다리지 않는다

`POST /conversations/:id/messages` 에서 채팅 턴이면, 방금 보낸 말과 **그 앞의 답변**을
함께 판정한다(불만은 늘 직전 답변을 향한다). 첫 메시지는 판정하지 않는다 — 그때의
"~하지 마" 는 이번 요청의 조건일 뿐이다.

- 넓은 정규식 체(`NEGATIVE_CUE`)를 먼저 통과해야 모델을 부른다. 평범한 새 질문 대부분이
  여기서 걸러져 턴마다 모델 호출이 붙지 않는다.
- 모델은 `{"negative": bool, "rule": "..."}` 한 줄만 답한다. 모양이 어긋나거나 길이
  (4~300자)를 벗어나면 버린다.
- 자체 시한(120초)으로 돈다. 사용자가 답변을 멈춰도 이미 한 말은 그대로다.
- 띄어쓰기·문장부호·대소문자만 다른 규칙은 같은 것으로 보고 다시 쌓지 않는다(위·아래 모두).
- 끄려면 `FEEDBACK_DETECT=false`.

### 4. 상한을 두되, 닿기 전에 묶어서 줄인다

반영 부분은 매 턴 프롬프트에 실리므로 4,000자에서 줄 경계로 자른다(`capActive`).
70% 를 넘으면 편집 창의 "비슷한 항목 묶기" 버튼이 강조된다. 누르면 모델이 합친 안을
돌려주고, 사용자가 보고 "편집기에 적용" → "저장" 해야 바뀐다. 정리안은 다음을 만족해야 받는다:
목록 줄만 남기고, 원래보다 짧다. 정리 대상은 반영 부분뿐이고 검토 대기는 그대로 둔다.
파일 전체는 40,000자를 넘으면 저장을 거절한다(413).

## 프롬프트 반영

`composeSystemPrompt(userPrompt, prohibitions)` 가 기본 프롬프트 뒤에
`## Things this user has asked you not to do` 절을 붙인다. 대화별 지시
(`## Additional instructions for this conversation`)는 그 뒤에 오고, 충돌하면 대화별 지시가 이긴다.
파일을 못 읽으면 목록이 없는 것으로 치고 대화는 계속된다.

## API

| 메서드 | 경로 | 내용 |
|---|---|---|
| GET | `/api/prohibitions` | `{markdown, activeChars, limitChars, warnRatio, fileMaxChars, pendingCount}` — 없으면 빈 틀 |
| PUT | `/api/prohibitions` | `{markdown}` 저장. 문자열 아니면 400, 너무 크면 413 |
| POST | `/api/prohibitions/consolidate` | `{proposal, before, after}` — 저장하지 않음. 항목 2개 미만 409, 실패 502 |

경로에 계정 id 가 없다. 늘 호출한 계정 자기 것이며, 관리자도 남의 목록을 보지 않는다.

## 화면

사이드바 설정(톱니) 메뉴 → 계정 → "하지 말 것 목록"(검토 대기 뱃지). 넓은 모달:
markdown 편집기, 반영 글자 수 / 상한, "검토 대기 N건 모두 반영", "비슷한 항목 묶기",
저장. 저장하지 않고 닫으려 하면 확인을 받는다.
